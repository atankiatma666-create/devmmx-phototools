Image dimensions versus file size: why online forms reject photos

Forms often set two limits that sound alike but measure different things: dimensions in pixels and file size in kilobytes. Knowing the difference saves a lot of failed uploads.

Two different measurements

Dimensions are how many pixels wide and tall an image is, such as 600 × 600. A pixel is one dot of colour.

File size is how much storage the file takes, measured in bytes. 1 KB is 1,024 bytes in this site’s tool, and 1 MB is 1,024 KB.

The two are related, but one does not decide the other.

How many pixels is that?

Multiply width by height. A 4000 × 3000 phone photo has 12,000,000 pixels, often called 12 megapixels. A 600 × 600 photo has 360,000 pixels, which is 3% of that.

Doubling both width and height gives four times the pixels. 1200 × 1200 has 1,440,000 pixels, four times as many as 600 × 600. File size tends to grow with the pixel count, though not exactly in step.

Why the same dimensions can give very different file sizes

Stored plainly, each pixel needs 3 bytes (red, green and blue). A 600 × 600 image would need 1,080,000 bytes, about 1,055 KB. JPEG stores far less by discarding detail that eyes notice least. How much it can discard depends on the picture:

  • Detail. A face against a plain wall compresses well. Leaves, gravel, patterned clothes and printed text need more bytes.
  • Noise. Photos taken in dim light have speckled grain. To JPEG, grain looks like detail, so it costs bytes.
  • Quality setting. Lower JPEG quality gives smaller files and more visible blocks and blur.

So two 600 × 600 photos might be 40 KB and 400 KB. That is why this site’s compressor measures each result instead of guessing.

What DPI does and does not change

DPI (or PPI) is a number stored in the file that says how large to print it. Changing it from 72 to 300 does not add or remove pixels, and it does not meaningfully change the file size.

DPI matters when a form gives a printed size. If a form asks for a photo of 3.5 cm × 4.5 cm at 300 DPI, convert to pixels: centimetres ÷ 2.54 × DPI. That gives about 413 × 531 pixels. These numbers are only an example of the arithmetic. Use the sizes your form actually states.

Why forms reject photos

  • Over the size limit. The most common reason. Compress to the stated maximum.
  • Under a minimum size. Some forms also reject files that are too small, to avoid unreadable photos. A tool that aims for a maximum may go below it, so check.
  • Wrong dimensions. The image is too wide, too narrow, or not within a stated pixel range.
  • Wrong shape. The form wants square or portrait, and the photo is landscape.
  • Wrong format. The form accepts JPEG only and the file is PNG, WebP or HEIC.
  • Different KB rules. Some systems count 1 KB as 1,000 bytes, others as 1,024. A file of 50,900 bytes passes a 50 KB limit under the 1,024 rule (51,200 bytes) but fails under the 1,000 rule (50,000 bytes). Aim a little below the limit to be safe, such as 48 KB for a 50 KB limit.

A sensible order of work

  1. Read the form’s official instructions for format, size, dimensions and shape.
  2. Crop to the required shape in your photo editor.
  3. If exact pixel dimensions are required, resize to them in an editor that lets you type the numbers.
  4. Compress to the size limit with the compressor, with smaller dimensions turned off so your chosen dimensions stay the same.
  5. Check the final file’s details and look at it zoomed in before uploading.
